# PART 10 — Five rules I strongly recommend you follow

These will save you a lot of trouble.

**1. Never allow Freebuff to build everything at once.**

Complete one module, test it and approve it before moving forward.

**2. Never let Freebuff change your architecture without approval.**

If it believes a technology should change, it must explain why and document the proposed change.

**3. Never accept a dashboard that only looks functional.**

A button that does nothing is not an implemented feature.

**4. Never compromise on multi-tenant security.**

An administrator from Institution A must never be able to access Institution B's private data.

**5. Keep your documentation updated.**

The documentation must evolve alongside the actual application.
